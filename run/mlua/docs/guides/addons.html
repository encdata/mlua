MLua/Addon API - MLua

Addon API

Learn how to extend MLua with custom Java-side services and globals.

Setup

At compile time, depend on mlua-api. At runtime, your addon should still require the mlua Forge mod through mods.toml.

dependencies {
    compileOnly fg.deobf("dev.mlua:mlua-api:0.2.0")
    runtimeOnly fg.deobf("dev.mlua:mlua:0.2.0")
}
MLuaApi only works after the Forge mod mlua installs its runtime bridge. Without that runtime mod present, MLuaApi calls throw an exception.

Compatibility Policy

mlua-api is the only supported Java integration surface for third-party addons. Addon code should avoid reaching into MLua runtime internals outside that API layer.

  • Stable target: dev.mlua.api.*, dev.mlua.core.MLuaContextView, dev.mlua.core.service.*, dev.mlua.module.*, and public enums used by those types.
  • Unstable internals: runtime implementation packages such as registry internals, UI internals, bindings, transformers, and other non-API packages.
  • Rule of thumb: if an addon can be written against mlua-api alone, that usage is intended to be supported across patch releases.

Naming Conventions

To avoid collisions with other mods, always use your Mod ID as the service name or as a prefix. For example, if your mod ID is vs2, name your service VS2 or vs2.

Creating an Addon Service

The easiest way to expose your mod's API is by extending MLuaReflectiveService. This base class automatically exposes all public methods to Lua.

1. Define the Service Class

Create a class that extends dev.mlua.core.service.MLuaReflectiveService. Methods starting with Get or Set will be automatically converted to live properties.

public class MyAddonService extends MLuaReflectiveService {
    private String status = "Initial";

    public MyAddonService(MLuaService.Context context) {
        super(context);
    }

    @Override
    public String name() {
        return "MyAddon";
    }

    // Exposes property MyAddon.Status
    public String GetStatus() {
        return this.status;
    }

    public void SetStatus(String value) {
        this.status = value;
    }

    // Exposes method MyAddon:PerformAction(arg)
    public void PerformAction(String arg) {
        System.out.println("Action: " + arg);
    }
}

2. Register the Service

Register your service in your mod constructor using MLuaApi:

MLuaApi.registerService("MyAddon", context -> new MyAddonService(context));

3. Use in Lua

Now you can access your service from any MLua script:

local MyAddon = Minecraft:GetService("MyAddon")

-- Access properties directly (no parenthesis needed)
print(MyAddon.Status) -- Calls GetStatus()
MyAddon.Status = "Running" -- Calls SetStatus("Running")

-- Call methods
MyAddon:PerformAction("Hello from Lua!")

Choosing the Right Hook

  • registerService: expose a Lua-facing API as a named service.
  • registerModule: advanced phase-aware integration, additional globals, listeners, or coordinated setup.
  • registerGlobal: small constants or helper values that belong directly in the global scope.
  • attachRegistries: finalize registry attachment only after all MLua registry registrations for that mod id are complete.

Registering Globals

If you want to put something directly in the global scope (available without GetService), use registerGlobal. You can filter globals by side (Client/Server) or by script type (e.g. only in .mixin.lua files).

// Global everywhere
MLuaApi.registerGlobal("my_mod", "VERSION", LuaValue.valueOf("1.0.0"));

// Global only on Client
MLuaApi.registerGlobal("my_mod", "IS_CLIENT", LuaValue.TRUE, Side.CLIENT);

// Global only in Mixin scripts
MLuaApi.registerGlobal("my_mod", "MIXIN_HELPER", myHelperTable, Side.BOTH, ScriptType.MIXIN);

Using Java Context

When your service is created, it receives an MLuaService.Context. This provides access to the public MLuaContextView, which is the stable execution-context contract for addons and avoids exposing runtime-only internals.

public MyAddonService(MLuaService.Context context) {
    super(context);
    MLuaContextView mlua = context.mlua();

    boolean client = mlua.isClient();
    boolean server = mlua.isServer();
    boolean registry = mlua.isPhase(RegistrationPhase.REGISTRY);
    String modId = mlua.ownerModId();
}
MethodDescription
isClient() / isServer()Check the current physical side.
isRegistration()True if currently in Mixin, Registry, or Commands phase.
isPhase(RegistrationPhase)Check for a specific boot phase.
isScriptType(ScriptType)Check if the current script is a Mixin, Server, Client, or Registry script.
ownerModId()The ID of the mod that owns the Lua script currently being executed.
server()Access the MinecraftServer instance. This is only meaningful during server-side execution.
filesRoot()Get the unique persistent data path for the current mod: run/mlua/data/<modid>/. Use this for config files, caches, or per-mod logs.

Advanced: Custom Modules

For more complex integrations (e.g. contributing to multiple phases, adding event listeners), implement the MLuaModule interface and register it via MLuaApi.registerModule(module).

Always use PascalCase (e.g. GetSomething) for methods if you want them to behave like properties (Something) in Lua.
